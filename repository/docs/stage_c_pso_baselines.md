# Stage C — extended PSO reference algorithms

## Scope

Stage C adds four literature-derived discrete-time PSO comparators to the six
baselines already present. The external benchmark method set therefore
contains **ten PSO variants plus the native CPSO**, eleven methods in total.
All external objective callbacks remain serial and are intended for quality
comparisons under a common function-evaluation (FE) budget. They do not measure
the parallel speedup of the native CPSO execution modes.

The implementations are intentionally explicit about choices that affect
reproducibility. They share bounds, population size, FE budget, deterministic
problem/seed labels, and the project boundary transformation unless the
published algorithm's boundary rule is an essential part of the method.
Initial coordinates and random streams are not forced to match across methods.

## Added methods

### SPSO-2011 (`spso2011`)

The implementation follows the standard SPSO-2011 geometric update and
adaptive random informant topology. The standard coefficients are

\[
\omega = \frac{1}{2\log 2},\qquad c=\frac12+\log 2.
\]

For each particle, the directed random informant graph is generated by letting
each particle inform `K=3` randomly selected particles and itself. Repeated
targets are allowed. Let `p_i` be the particle's personal best and `l_i` the
best personal-best position among the particle and its informants. The gravity
centre is

\[
G_i=x_i+c\frac{p_i+l_i-2x_i}{3}.
\]

When `l_i=p_i`, the standard two-point special case is used:

\[
G_i=x_i+c\frac{p_i-x_i}{2}.
\]

A random point is drawn in the hypersphere centred at `G_i` with radius
`||G_i-x_i||`. The default SPSO-2011 distribution uses a uniformly random
direction and a uniformly random radius in `[0, ||G_i-x_i||]`; it is **not**
uniform in hypersphere volume. Coordinates are normalized to the unit box
before the geometric operation. Initial velocity components are sampled as
`U(-x_i, 1-x_i)` in this normalized box. When a proposed coordinate crosses a
boundary, that coordinate is clipped and the corresponding velocity
component is multiplied by `-0.5`. The random informant graph is rebuilt after
a generation that does not improve the global best. These choices are recorded
in the per-run parameter metadata.

The implementation follows the standard algorithmic description, but does
not claim bitwise identity with a particular external SPSO-2011 software
package; RNG streams and floating-point evaluation orders are necessarily
implementation-specific.

### FIPS (`fips_ring`)

The Fully Informed Particle Swarm uses information from every member of a
particle's neighborhood instead of only the best neighbor. We use a periodic
ring with the two adjacent particles as informants (the focal particle is not
included in this two-node set):

\[
 v_i^{t+1}=\chi\left(v_i^t+
 \frac{1}{|N_i|}\sum_{j\in N_i}
 R_{ij}\odot(p_j-x_i^t)\right),
 \quad R_{ij,k}\sim U(0,\phi),
\]

with `phi = 4.1` and the Clerc constriction factor

\[
\chi=\frac{2}{\phi-2+\sqrt{\phi^2-4\phi}}.
\]

The FIPS neighborhood is deliberately fixed and recorded; changing topology
would define a different FIPS experiment.

### Competitive Swarm Optimizer (`cso`)

CSO randomly pairs the current population at every generation. In each pair,
the better particle is the winner and remains unchanged; the loser is updated
using the winner, the previous-generation swarm mean, and its previous
velocity:

\[
 v_l^{t+1}=R_1\odot v_l^t+R_2\odot(x_w^t-x_l^t)
 +\varphi R_3\odot(\bar{x}^t-x_l^t),\qquad
 x_l^{t+1}=x_l^t+v_l^{t+1},
\]

where independent coordinates of each `R_k` are uniform on `[0,1]` and
`phi = 0.1`. Initial velocities are zero. The algorithm evaluates only the
losers after initialization, so one complete generation consumes `N/2` new
FE, not `N`. The global FE counter and stored history use the actual number of
objective calls. The campaign still uses an even population (40 by default),
so the common benchmark FE budgets remain exactly divisible. The project
clamp-and-restitution map is applied at the bounds and recorded as an explicit
implementation adaptation.

CSO is PSO-derived, but it does not use personal-best or global-best positions
in its update equation. It should not be described as a conventional gbest/lbest
PSO.

### DMS-PSO (`dms_pso`)

The implemented method is the basic dynamic multi-swarm PSO without the
optional quasi-Newton local-search extension. At initialization, the population
is randomly partitioned into small sub-swarms. Each particle uses its personal
best and the best personal-best position in its current sub-swarm:

\[
 v_i^{t+1}=\omega_t v_i^t+2r_1\odot(p_i-x_i^t)
 +2r_2\odot(l_i-x_i^t),\quad x_i^{t+1}=x_i^t+v_i^{t+1}.
\]

The inertia decreases linearly from `0.9` to `0.2`. Sub-swarms are randomly
regrouped every `R=5` generations. The target sub-swarm size is `m=3`; for the
shared population of 40, the remainder is absorbed into the final group, so
all particles belong to a group of size at least two. This is a documented
population-compatibility detail rather than a claim that all groups have
exactly three members.

## Shared protocol and limitations

- `cpso_continuous` plus ten PSO variants are evaluated on the same problem,
population, exact FE budget and deterministic seed label.
- The algorithm-specific update laws, initial velocity policies, social
information, topology and boundary treatment differ by design. Equal FE does
not make their trajectories or update counts identical.
- CSO consumes half as many evaluations per generation. Its history is stored
against actual FE, so plots and checkpoints must use `history_evaluations`,
not assume a common generation count.
- DMS-PSO's regrouping schedule and final-group remainder policy are recorded.
- The fixed population allows direct FE accounting but is not necessarily the
paper's recommended population policy for every method. In particular,
SL-PSO continues to use the documented fixed-population comparison policy.
- These ten variants form a representative comparison set, not an exhaustive
claim of current SOTA. They also do not replace CMA-ES or differential-evolution baselines, which are outside Stage C's PSO-only scope.

## Stage C configurations

The new configurations deliberately separate integration checks from useful
pilot work:

| File | Purpose | Size |
|---|---|---:|
| `bbob_stageC_smoke.json` | All methods through real COCO wrappers on a tiny subset | 132 runs |
| `bbob_stageC_pilot.json` | Selected BBOB functions, D=5/20, instances 1–5 | 770 runs |
| `bbob_largescale_stageC_smoke.json` | Large-scale adapter and all methods | 132 runs |
| `cec2013_stageC_smoke.json` | All methods on CEC F1 with a small FE budget | 11 runs |
| `cec2013_stageC_pilot.json` | Six representative LSGO functions, three seeds | 198 runs |

Smoke runs validate execution only; they are not inferential evidence. The
pilot campaigns are intended to expose implementation faults, compare
convergence profiles and check run-time feasibility before a confirmatory
protocol is frozen. Do not tune parameters using confirmatory test results.
